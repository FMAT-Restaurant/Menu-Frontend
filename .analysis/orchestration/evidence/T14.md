## 1. Resumen de Implementación

### 1.1 Bloqueo de Campos y Handler contra Envíos Simultáneos (`P02`)
- En `src/features/recipes/RecipeFormDialog.tsx`:
  - Se introdujo `isSubmittingRef = useRef(false)` como cerrojo sincrónico.
  - Se blindaron los métodos de despacho `save`, `executeCreationFlow` y `executeEditSave` para rechazar cualquier invocación reentrante si `busy || isSubmittingRef.current`.
  - Se deshabilitaron incondicionalmente todos los campos durante el envío (`disabled={busy}`):
    - Campo de texto `name`
    - Área de texto `description`
    - Área de texto `instructions`
    - Botón `+ Agregar insumo`
    - Controles de búsqueda y paginación de inventario
    - Selectores de insumo de cada fila
    - Entradas numéricas de cantidad de cada fila
    - Botones de eliminación de fila `×`
    - Botón de cierre superior `×` y botón `Cancelar` inferior.
  - Los handlers de cambio (`handleNameChange`, `handleDescriptionChange`, `handleInstructionsChange`, `handleAddSupply`, `handleRemoveSupply`, `handleSupplyChange`) retornan inmediatamente si `busy || isSubmittingRef.current`.

### 1.2 Recuperación Diferenciada POST vs. PATCH y Revisión (`P04`)
- **Creación (POST):**
  - Mantiene el controlador de idempotencia `OperationAttemptController` con UUID v4 y sealed JSON payload de T02B.
  - La pérdida de respuesta o timeout conserva el borrador editable y permite reintentar con la misma clave y payload snapshot original para recuperar el 201 y mismo `recipeId`.
  - Si hubo modificaciones locales posteriores al despacho, se preservan para guardado explícito vía `onCreatedWithPendingEdits`.
  - Al cerrar o cancelar el formulario, se invoca `controller.abandonFlow()`, impidiendo que respuestas tardías seleccionen o modifiquen el contexto.
- **Edición (PATCH):**
  - En el contrato OpenAPI, el PATCH de recetas no utiliza clave de idempotencia; opera bajo concurrencia optimista con ETag fuerte de apertura (`If-Match`).
  - Ante un error 412 (`PRECONDITION_FAILED`) o incertidumbre en la mutación, se requiere explícitamente revisión (`setReviewRequired(true)`).
  - Se prohíbe terminantemente la renovación automática de ETag y el auto-reenvío silencioso.
  - El usuario puede consultar el estado del servidor mediante `"Revisar receta actual"` (`handleReviewRecipe`), contrastar los datos y decidir si adoptar los datos remotos o aplicar su borrador sobre la nueva versión revisada.

### 1.3 Semántica Accesible de `<fieldset>` y `<legend>` (`P05`)
- En `src/features/recipes/RecipeFormDialog.tsx`:
  - Se reestructuró la sección de insumos para colocar `<legend>Insumos del inventario</legend>` como **primer hijo directo** de `<fieldset className="recipe-supplies-section">`, seguido por `<div className="recipe-supplies-section__header">`.
  - Esto garantiza que los lectores de pantalla y el árbol de accesibilidad asocien de forma nativa el nombre accesible al grupo:
    `screen.getByRole("group", { name: "Insumos del inventario" })`.

### 1.4 Claves Deterministas de Instancia y Eliminación de Estado Global (`P06`)
- Se erradicó la variable mutable global `let rowSeed = 0;` y su función impura `nextRowKey()`.
- Se configuró la inicialización de filas de suministros mediante claves deterministas de instancia:
  - Filas iniciales: `supply-row-${idx + 1}` basadas en la posición.
  - Contador de instancia encapsulado: `rowCounterRef = useRef(initialSuppliesCount)`.
  - Filas agregadas dinámicamente: `createNextRowKey()` incrementa el ref local de la instancia del diálogo.
  - Ni el remonte ni la doble ejecución de inicializadores en React StrictMode alteran un contador compartido ni desajustan las identidades de las filas.

### 1.5 Atribución Contractual de Errores al Eliminar Recetas (`P11`, `P16`)
- En `src/api/idempotencyResponse.ts`:
  - Se extendió `analyzeNonIdempotentWriteError` para identificar rechazos contractuales de negocio: cuando el estado es 409 o 422 y se recibe `details.code === "RECIPE_IN_USE"` o `offerIds` no vacío, clasifica el error como `kind: "resource_in_use"`.
  - Asimismo clasifica 403 como `FORBIDDEN` ("No tienes permisos para modificar este recurso") y 412 como `PRECONDITION_FAILED`.
- En `src/features/recipes/RecipePage.tsx`:
  - En `handleConfirmDelete`, se analiza el error con `analyzeNonIdempotentWriteError(err)`:
    - `resource_in_use`: Muestra el mensaje contractual de que la receta está referenciada por una oferta vigente.
    - `precondition_conflict` (412): Muestra advertencia de conflicto de concurrencia.
    - `forbidden` (403): Muestra mensaje de falta de permisos.
    - `uncertain_outcome` / corte de red: Cierra el diálogo de confirmación, refresca la lista mediante `listRecipes` habitual y advierte que se consultó la lista para verificar el estado actual.
    - Otros errores: Muestra el mensaje real del servidor o genérico de transporte.

### 1.6 Bloqueo contra Escape/Cancel y Gestión de Foco en Diálogo de Borrado (`P12`)
- En `src/features/recipes/RecipePage.tsx`:
  - Se implementó `deleteTriggerRef` y `previousRecipeToDeleteRef`.
  - Al abrir el diálogo, `deleteTriggerRef` registra el botón que disparó la acción.
  - Al presionar `Escape` en teclado o disparar el evento nativo `cancel` en `<dialog>`:
    - Si `isDeleting === true`, se ejecuta `event.preventDefault()` y `event.stopPropagation()`, manteniendo el diálogo abierto y los botones bloqueados.
    - Si `isDeleting === false`, el diálogo se cierra normalmente y en el post-render se devuelve el foco a `deleteTriggerRef.current`.
  - Al resolver el borrado o cancelar en reposo, el foco retorna automáticamente al disparador original.

### 1.7 Pruebas de Validación con 0 Llamadas de Persistencia (`P15`)
- En `src/features/recipes/RecipePage.test.tsx`:
  - La prueba de validación verifica secuencialmente cada campo inválido: nombre vacío, descripción vacía, instrucciones vacías, insumo no seleccionado, cantidad <= 0.
  - En cada caso inválido, se comprueba estrictamente:
    `expect(repository.createRecipe).not.toHaveBeenCalled();`
  - Al ingresar todos los valores válidos y enviar, se valida:
    `expect(repository.createRecipe).toHaveBeenCalledTimes(1);`
    con el payload exacto esperado.
