## 1. Resumen de Implementación

### 1.1 Configuración y Cliente Independiente de Inventario (`DEC-02`)
- **`public/runtime-config.js`:**
  Se declaró la variable de entorno runtime `inventoryApiBaseUrl`:
  ```javascript
  window.MENU_CONFIG = Object.freeze({ apiBaseUrl: "", inventoryApiBaseUrl: "" });
  ```
- **`src/App.tsx`:**
  Se extendió la interfaz global `Window` y se instanció el cliente axios para Inventario de forma independiente al de Menu:
  ```typescript
  const menuBaseUrl = window.MENU_CONFIG?.apiBaseUrl || "/api/v1";
  const inventoryBaseUrl = window.MENU_CONFIG?.inventoryApiBaseUrl || menuBaseUrl;

  const defaultRepository = createMenuApi(
    axios.create({ baseURL: menuBaseUrl }),
    axios.create({ baseURL: inventoryBaseUrl }),
  );
  ```
- **`src/api/menuApi.ts`:**
  `createMenuApi` ahora admite `inventoryClient: AxiosInstance = client`. El método `listInventoryItems` utiliza `inventoryClient.get("/inventory/items", ...)` preservando el contrato público y manteniendo retrocompatibilidad total.
- **`src/api/menuApi.test.ts`:**
  Se añadió un caso de prueba que verifica el enrutamiento independiente hacia `inventoryClient` y `client` cuando sus URLs base difieren.

### 1.2 Unión Discriminada de Props por Modo en `RecipeCard` (`P01`)
- **`src/features/recipes/RecipeCard.tsx`:**
  Se reemplazó la interfaz abierta de callbacks opcionales por una unión discriminada estricta:
  ```typescript
  export interface ManagementRecipeCardProps extends BaseRecipeCardProps {
    mode: "management";
    onEdit: (recipe: RecipeSummary) => void;
    onDelete: (recipe: RecipeSummary) => void;
    onSelect?: never;
  }

  export interface SelectionRecipeCardProps extends BaseRecipeCardProps {
    mode: "selection";
    onSelect: (recipe: RecipeSummary) => void;
    onEdit?: never;
    onDelete?: never;
  }

  export type RecipeCardProps = ManagementRecipeCardProps | SelectionRecipeCardProps;
  ```
  Combinaciones inválidas no compilan en TypeScript.

### 1.3 Preservación de Insumos e Identidad fuera de la Página de Inventario (`P03`)
- **`src/features/recipes/RecipeFormDialog.tsx`:**
  - Se introdujo un mapa de insumos conocidos (`knownItems: Map<string, InventoryItem>`), inicializado con los insumos del detalle de Menu (`activeRecipe.supplies[].inventoryItem`) y poblado con cada página o búsqueda de inventario.
  - Al renderizar cada fila de la tabla de insumos, si el `inventoryItemId` seleccionado no se encuentra en la página actual de resultados de inventario, se genera dinámicamente su `<option>` con el nombre obtenido del detalle o del registro previo.
  - La columna de unidad de medida (`getUnitForItem`) extrae la unidad desde `knownItems` o `activeRecipe.supplies`, manteniendo la visibilidad de la unidad y del valor sin requerir que el insumo resida en la página actual de la API.
  - Al guardar, el formulario envía únicamente `{ inventoryItemId, quantity }`, garantizando persistencia exacta de lo visible.

### 1.4 Paginación y Búsqueda Desacopladas de Inventario con Reintento Independiente (`P07`, `P08`)
- **`src/features/recipes/RecipeFormDialog.tsx`:**
  - Búsqueda y paginación dedicadas dentro de la sección de insumos del diálogo mediante `repository.listInventoryItems`. No se descarga todo el inventario al abrir ni se impone tope de 100 artículos (artículo 101 alcanzable en página posterior).
  - Estado de error y reintento (`inventoryError`, `inventoryRetryCount`) totalmente aislado: si falla la consulta de inventario, se muestra la causa y un botón "Reintentar". El borrador de la receta (nombre, descripción, pasos, insumos ya cargados) permanece intacto. Al reintentar, se recuperan los artículos y se permite continuar la selección.

### 1.5 Carga Fuerte de Detalle y Cancelación de Carreras de Apertura (`P09`, `P10`)
- **`src/features/recipes/RecipePage.tsx`:**
  - Se eliminó el `catch` anterior que degradaba un fallo de `getRecipe` a abrir el resumen como receta completa. Ante error, se muestra un aviso y el editor no se abre (`P09`).
  - Se añadieron `openingRecipeIdRef` y `openingControllerRef`. Si se solicita abrir la receta A y posteriormente la receta B, la petición de A es abortada; si A resolviera después de B, su resolución es descartada y no sustituye al editor vigente (`P10`).

### 1.6 Consulta Confirmada por Modo y Paginación de Recetas (`P07`, `P13`, `P14`)
- **`src/features/recipes/RecipePage.tsx`:**
  - Manejo de una única consulta confirmada por modo: sincronizada con URL en administración y en estado local en modo selección, con `draftSearch` reservado para texto no enviado. La búsqueda reinicia la página a 1 sin disparar cargas duplicadas con parámetros antiguos (`P13`).
  - Navegación paginada de recetas (`<nav className="pagination">`) que permite alcanzar la receta 51 (`P07`).
  - Búsqueda efectiva: al buscar "Pollo", la respuesta del backend sustituye de inmediato los resultados anteriores (`P14`).

### 1.7 Preservación de Instrucciones e Insumos al Editar Nombre (`P17`)
- **`src/features/recipes/RecipePage.test.tsx`:**
  - El caso de edición de receta se reforzó con aserciones exactas: al modificar el nombre, se comprueba que las instrucciones y el arreglo completo de insumos con sus cantidades exactas coincidan estrictamente con el detalle original.

### 1.8 Suite End-to-End (`e2e/recipes.spec.ts`)
- Se implementó la suite completa de Playwright con 4 escenarios reales:
  1. Búsqueda y paginación en biblioteca administrativa alcanzando la receta 51 en página 2.
  2. Creación de receta navegando a la página 2 de inventario para seleccionar el insumo 101 y verificar el payload POST enviado.
  3. Aislamiento de fallo de inventario 503, verificación de error con reintento y persistencia del borrador mientras se recupera el servicio.
  4. Modo selección (`/recipes?mode=selection`) con presencia de botón "Asignar" y ausencia de acciones administrativas.
