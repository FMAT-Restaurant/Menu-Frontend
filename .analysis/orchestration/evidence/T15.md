## 1. Resumen de Implementación

### 1.1 Ruta Comodín 404 (`src/App.tsx`)
- Se implementó el componente `NotFoundPage` renderizado en la ruta `path="*"`.
- Proporciona una explicación clara: *"La ruta solicitada no existe o fue movida. Verifica la dirección o regresa al catálogo de entradas."*
- Proporciona un enlace interactivo y accesible (`<Link to="/" className="button button--primary">Volver al catálogo</Link>`).
- Este componente no importa dependencias pesadas, manteniendo la carga inicial ligera y sin comprometer el diferimiento.

### 1.2 Carga Diferida con Code Splitting (`React.lazy` + `Suspense`)
- Todas las vistas de características se importan de forma dinámica con `React.lazy`:
  - `CatalogPage` (`src/features/catalog/CatalogPage`)
  - `CategoryPage` (`src/features/categories/CategoryPage`)
  - `EntryFormPage` (`src/features/entries/EntryFormPage`)
  - `OffersPage` (`src/features/offers/OffersPage`)
  - `OfferFormPage` (`src/features/offers/OfferFormPage`)
  - `RecipePage` (`src/features/recipes/RecipePage`)
- Se envolvió el enrutador en `<Suspense fallback={...}>` con un indicador accesible (`role="status" aria-live="polite"`).
- **Verificación en el Build (`vite build`):**
  - Bundle monolítico inicial anterior: `index.js 488.32 kB`.
  - Con code splitting:
    - `index-BZ64ICCW.js`: `346.68 kB` (-141.64 kB transferidos al inicio).
    - `CatalogPage-Czt0RlTA.js`: `16.07 kB`
    - `CategoryPage-DYYrK1o6.js`: `14.17 kB`
    - `OffersPage-B24PScSx.js`: `13.95 kB`
    - `RecipePage-D8NVbWlT.js`: `23.03 kB`
    - `EntryFormPage-DsoCpSoO.js`: `27.31 kB`
    - `OfferFormPage-DjNJJzJA.js`: `40.11 kB`

### 1.3 Aislamiento de Pruebas y Limpieza de Historial (`src/App.test.tsx`)
- Todos los casos de prueba inyectan explícitamente un repositorio simulado con `createRepository({...})`, asegurando que ninguna prueba utilice `defaultRepository` ni realice peticiones HTTP reales.
- Se implementaron ganchos `beforeEach` y `afterEach` que ejecutan `cleanup()` y `window.history.replaceState({}, "", "/")`, previniendo la contaminación de URL o estado entre tests aun si ocurre una falla en aserciones.
- Se agregaron aserciones asíncronas (`findBy*`) para esperar la resolución limpia de los componentes cargados con `React.lazy`.
- Se verificaron: catálogo raíz (`/`), alias de redirección (`/menu`), recetas (`/recipes`), categorías (`/categories`), ofertas (`/entries/:id/offers`), formulario de entradas (`/entries/new` y `/entries/:id/edit`), formulario de ofertas con retorno contextual (`/entries/:id/offers/:id/edit`), y ruta 404 (`/ruta-inexistente-404`).

### 1.4 Pruebas E2E de Enrutamiento y Red (`e2e/app-routes.spec.ts`)
- Se creó la suite Playwright `e2e/app-routes.spec.ts`:
  - `unknown route shows accessible 404 message and allows returning to the catalog (R01)`: comprueba el mensaje 404 y el retorno navegable hacia `/`.
  - `alias /menu redirects to catalog root / (R01, R04)`: comprueba la redirección funcional a la raíz.
  - `loads editor chunks on demand and avoids downloading them on initial catalog load (R02)`: monitorea el tráfico de red (`page.on("request")`) confirmando que `OfferFormPage` NO se descarga al visitar `/`, y que el chunk de `EntryFormPage` se descarga únicamente al navegar a `/entries/new`.
